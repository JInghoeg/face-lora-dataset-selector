# Face LoRA Dataset Selector

一个给 **真人 / 人脸 LoRA 数据集** 用的本地筛图工具。

如果你手里有一大批照片，正在做这些事：

- 从几百张图里挑出更适合训练的那一批；
- 清掉模糊、太暗、太小、重复度高的图片；
- 检查正脸、3/4、侧脸、半身、全身是不是太偏科；
- 从连拍、视频抽帧或写真图集中去掉大量近重复图；
- 最后再人工确认，而不是完全相信自动评分；
- 顺手处理字幕、水印或图片上的文字区域；

这个工具就是为这类流程做的。

它不会替你“一键决定哪些图一定最好”，而是先帮你把数据集整理得更有条理，让人工筛选从“几百张逐张翻”变成“先看最值得看的”。

---

## 适合什么场景？

### 1. 人物 LoRA 数据集初筛

例如你收集了 200～500 张同一个人的照片，但最终只想留下几十到一百多张。

程序可以先帮你找出：

- 明显模糊或质量较差的图；
- 人脸太小、曝光不理想的图；
- 大量近重复图片；
- 姿态和景别过于集中的问题。

然后再由你自己决定哪些保留。

### 2. 检查角度和景别是否够丰富

训练真人 LoRA 时，很容易出现：

- 几乎全是正脸；
- 左 3/4 很多，右 3/4 很少；
- 全是大头照，没有半身和全身；
- 某一类图片数量特别多。

工具会把这些信息整理出来，方便快速查看和补齐缺口。

### 3. 连拍、视频抽帧、图集去重

如果素材来自：

- 连拍；
- 视频抽帧；
- 同一套写真；
- 同一场活动的大量相似照片；

通常会有很多“看起来差不多”的图片。

程序会把近重复图片分组，并优先把质量更好的候选放在前面，减少人工来回比较。

### 4. 字幕 / 水印 / 文字区域处理

单独提供文字处理页，可以：

- 自动检测图片中的文字区域；
- 手动增删检测框；
- 预览修复效果；
- 批量输出到新目录。

支持 TELEA、Navier-Stokes，以及可选的 MI-GAN AI 修复。

> 原图不会被覆盖。

## 为什么这样设计这套质量评估系统？

我们没有用一个“总分模型”直接决定图片好坏，因为 **LoRA 数据集质量不是单一问题**：脸本身清不清楚、整张图有没有明显失真、角度是否丰富、是不是重复图，本来就应该分开判断。

所以当前系统把几类已经有公开论文、基准或成熟工程实现的方法组合在一起：

| 负责什么 | 使用的方法 | 为什么选它 |
| --- | --- | --- |
| **先确认脸是否存在、大小是否够用** | **YuNet** | OpenCV Zoo 的轻量人脸检测模型，在 WIDER Face 上有公开评测；速度快、CPU 友好，适合作为大量图片的第一层检测。 |
| **判断“这张脸本身适不适合作为身份训练素材”** | **eDifFIQA-T** | 专门做人脸图像质量评估（FIQA），论文发表于 IEEE TBIOM；eDifFIQA 系列也进入过 NIST FATE Quality 评测，T 版同时被收录进 OpenCV Model Zoo。相比只看整图清晰度，它更贴近“人脸能不能用”。 |
| **判断整张照片有没有明显失真或质量问题** | **BRISQUE** | 经典无参考图像质量评估方法，发表于 IEEE Transactions on Image Processing，并被 OpenCV Quality 模块长期提供。它不需要“原始无损参考图”，很适合真实网络图片。 |
| **判断头部朝向** | **3DDFA-V2** | ECCV 2020 的 3D 人脸对齐方法，可稳定估计 yaw / pitch / roll，用来区分正脸、3/4、侧脸，而不是靠文件名或简单 2D 规则猜角度。 |
| **判断近景、半身、全身等景别** | **MediaPipe Pose** | Google 的人体姿态方案，可输出 33 个身体关键点。这里不用它评“美不美”，而是判断身体可见范围，辅助数据集构图覆盖。 |
| **处理连拍 / 抽帧近重复** | **pHash + 质量排序** | 感知哈希适合找“视觉上几乎一样”的图片；检测到一组近重复后不会直接全删，而是结合质量指标优先保留更好的代表图。 |

### 推荐不是简单的“质量 Top N”

当前自动推荐实际走的是：

**基础可用性检查 → 质量门槛 → 近重复组只取最佳代表 → 按景别 × Yaw 分桶 → 桶内按质量排序 → 人工最终确认**

这样做的目的，是避免一个很常见的问题：如果只选质量最高的前 60 张，最后很可能 50 张都是正脸大头照。

本项目更看重的是：**单张图要过关，同时整套数据也要有覆盖。**

> 需要区分两件事：YuNet、eDifFIQA、BRISQUE、3DDFA-V2、MediaPipe 等底层方法都有公开论文、基准或成熟官方实现；而本项目使用的具体推荐阈值和组合逻辑，是针对真人 LoRA 数据集筛选做的工程化策略，不把它们冒充为“行业统一标准”。

参考：
- [eDifFIQA — official repository / IEEE TBIOM](https://github.com/LSIbabnikz/eDifFIQA)
- [BRISQUE — OpenCV Quality](https://docs.opencv.org/4.x/d8/d99/classcv_1_1quality_1_1QualityBRISQUE.html)
- [3DDFA-V2 — ECCV 2020](https://github.com/cleardusk/3DDFA_V2)
- [YuNet — OpenCV Zoo](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet)
- [MediaPipe Pose Landmarker — Google](https://developers.google.com/mediapipe/solutions/vision/pose_landmarker)

## 快速开始

### 环境

- Windows 10 / 11 x64
- Python 3.9–3.12
- 推荐 Python 3.12 x64
- 不要求 NVIDIA 显卡，也不要求 CUDA

暂不建议 Python 3.13+。

### 最简单的安装方式

1. 安装 **Python 3.12 x64**
2. 下载或克隆本仓库
3. 双击：

```text
安装.bat
```

安装脚本会在项目目录创建独立的 `.venv` 环境并安装所需依赖，不会把这些包直接装进你的其他 Python 项目。

安装完成后，双击：

```text
启动.bat
```

即可运行。

### 手动安装

如果你更习惯命令行，也可以在项目目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

`启动.bat` 会优先使用项目自己的 `.venv`；没有 `.venv` 时才会尝试系统里的 Python 3.9–3.12。

## 怎么用？

### 人脸 LoRA 数据集筛选

推荐按这个顺序：

1. **选择训练图片目录**
2. 等待程序完成分析
3. 先看自动给出的 **推荐 / 备选 / 淘汰**
4. 再按 **景别、Yaw、Pitch、质量、重复组** 等条件筛选查看
5. 对自动判断不满意时，直接手动修改状态
6. 最后导出“推荐”图片到新目录

自动结果只是帮你缩小范围，**人工判断始终优先**。

比较实用的做法是：

- 先清明显差图；
- 再处理重复图；
- 然后检查角度 / 景别覆盖；
- 最后再看整体人物一致性和你自己的训练目标。

### 文字 / 水印处理

推荐流程：

1. 选择输入图片目录
2. 选择一个新的输出目录
3. 点击 **扫描文字**
4. 检查程序检测出的文字区域
5. 需要时手动添加或删除区域
6. 选择修复方式
7. 先用 **预览修复** 检查效果
8. 确认后再批量处理

如果文字压在人眼、五官等关键身份特征上，不建议为了“救图”强行修复；这类图片通常直接不用更稳。

## 自动结果怎么看？

### 推荐

代表当前自动规则认为比较值得优先保留的图片。

### 备选

不一定有问题，只是可能：

- 质量稍弱；
- 和其他图比较相似；
- 某个角度已经很多；
- 人脸偏小；
- 或没有明显进入优先推荐范围。

### 淘汰

通常是存在比较明显的问题。

不过所有自动判断都可以手动修改，不会强制替你删除图片。

## MI-GAN AI 修复

MI-GAN 是可选功能，模型文件不会直接放在仓库里。

第一次选择 **AI 修复（MI-GAN）** 时，如果本地没有模型，程序会自动从上游下载约 28 MB 的模型文件，并在下载完成后做完整性校验。

模型会保存到：

```text
models/migan_pipeline_v2.onnx
```

如果下载失败，仍然可以继续使用：

- TELEA
- Navier-Stokes

不影响其他筛图功能。

## 常见问题

### 会不会修改我的原图？

不会。

筛选导出和文字修复都会写到新的位置，源图片保持不变。

### 为什么第一次分析比较慢？

第一次需要实际分析图片。

后续再次打开同一个数据集时，会复用本地缓存；没有变化的图片通常不需要全部重新分析。

### `cache/` 可以删吗？

可以。

这里保存的是分析结果和缩略图。删除后不会影响原图，只是下次会重新分析相关内容。

### 自动推荐是不是越高分就一定越适合训练？

不是。

质量分数、角度、景别、重复检测都只是辅助信息。一个好的 LoRA 数据集还需要考虑人物一致性、表情、服装、姿态和整体覆盖，所以最终仍建议人工确认。

### 可以拿来筛二次元 / 非真人数据集吗？

当前版本主要按 **单人真人 Face LoRA** 设计。其他类型图片可能能运行，但自动判断未必有参考价值。

### 为什么有些重复图没有被识别？

近重复检测更适合非常相似的连拍、抽帧和构图接近的图片。

如果两张照片只是“同一场景、同一套衣服”，但姿态或构图变化较大，不一定会被判成重复，这是正常的。

### 提示缺少依赖怎么办？

最简单的处理方式是重新双击：

```text
安装.bat
```

它会继续使用项目自己的 `.venv` 并补齐缺少的依赖，然后再重新运行 `启动.bat`。

## 当前版本的边界

当前版本重点解决：

- 单人真人 Face LoRA 数据集筛选；
- 质量与人脸可用性检查；
- 近重复整理；
- 姿态 / 景别覆盖检查；
- 人工复核与导出；
- 字幕、水印和文字区域处理。

目前还没有内置：

- 多宫格图片自动拆分；
- 杂志封面 / 扫描页主体自动裁取。

这类素材建议先拆分或裁取，再进入当前筛选流程。
