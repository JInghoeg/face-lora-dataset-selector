# v0.3 AI Sync Schema

Status: REVIEWED DESIGN CANDIDATE
Parent plan: docs/V0.3_EXECUTION_PLAN.md
Tracking issue: #2

## 1. Goal

The selector must synchronize the actual local dataset or current View with ChatGPT without requiring the user to describe hundreds of images manually.

The round trip is:

```
Selector
  -> AI Review Bundle
  -> ChatGPT review
  -> review_patch.json
  -> Selector AI suggestion layer
  -> user explicitly accepts/rejects suggestions
```

AI suggestions never silently overwrite manual decisions.

## 2. Bundle identity

Every export gets a unique `bundle_id`.

Recommended form:

```
bundle_<UTC timestamp>_<short random/id>
```

The bundle records:

- schema_version
- bundle_id
- created_at
- app_version
- dataset_root_label
- source_scope: dataset / saved_view / current_view
- source_view_id when applicable
- sample_count

Do not include an absolute Windows path in the AI-facing metadata.

## 3. Bundle layout

```
AI_Review_Bundle/

```

## 5. manifest.csv

Human-readable / spreadsheet-friendly companion.

One row per sample.

Required flat columns:

- sample_id
- filename
- relative_path
- width
- height
- effective_status
- manual_status
- eligibility
- face_count
- face_ratio
- face_px
- face_quality
- brisque
- sharpness
- brightness
- yaw
- pitch
- roll
- angle_class
- pitch_class
- person_scale
- duplicate_group
- review_flag_codes
- hard_reject_codes

Nested face boxes stay canonical in manifest.json.

## 6. summary.json

Dataset-level summary for quick AI understanding.

Minimum:

- total samples
- status counts
- eligibility counts
- shot-size distribution
- yaw distribution
- pitch distribution
- duplicate-group count / member count
- samples with secondary-face flags
- samples with no detected face
- samples with hard rejects
- current View description if exported from a View

Later additions may include outfit/source/semantic-similarity distributions.

## 7. Contact sheets

Contact sheets are a required visual index.

Every tile must show:

- sample_id
- short filename
- effective status
- optional eligibility marker

Rules:

- preserve readable image size;
- split into multiple pages rather than making hundreds of tiny tiles;
- no absolute local path;
- duplicate-group sheets use the same stable IDs;
- current View export should have its own contact sheets.

## 8. Optional originals

Original/full-resolution images are optional because many reviews can begin from contact sheets.

User choices:

- no originals
- current View originals
- selected samples only
- requested samples only

This is not a model-size optimization; it is a practical bundle-size/control option.

## 9. review_patch.json

Canonical import format:

```json
{
  "schema_version": 1,
  "bundle_id": "bundle_...",
  "created_at": "...",
  "suggestions": [
    {
      "sample_id": "img_7f2a91d43b2ce801",
      "content_sha256": "...",
      "suggested_eligibility": "REVIEW",
      "suggested_status": "备选",
      "flags": ["possible_redundancy"],
      "note": "Compare with img_abcd...",
      "request_full_resolution": true
    }
  ]
}
```

## 10. Import validation

Before any suggestion is accepted into the local suggestion layer:

1. schema_version must be supported;
2. bundle_id must be known or explicitly accepted as external;
3. sample_id must exist;
4. content_sha256 must match when present;
5. duplicate sample_id entries in one patch are invalid;
6. unknown IDs are reported and skipped;
7. stale/changed samples are reported;
8. malformed records do not partially alter manual state.

## 11. AI suggestion state

Imported suggestions are stored separately from manual state.

Suggested UI concepts:

- AI 建议
- AI 备注
- 需要原图复核
- 接受
- 拒绝
- 清除

Accepting a suggestion is a deliberate user action.

Even after acceptance, preserve enough audit information to know that the change originated from an AI suggestion.

## 12. Stale patch behavior

Because the dataset may continue changing:

- sample_id identifies a local sample instance; content SHA-256 independently verifies image content;
- unchanged same-path samples keep their ID;
- renamed/moved samples keep their ID when the cached content match is unambiguous;
- byte-identical duplicate files still have distinct sample IDs;
- if multiple identical old copies are moved in an ambiguous way, the selector must not guess instance identity;
- edited/replaced images receive a new sample_id;
- a patch for old content must never attach to new content just because the filename matches.

This is why sample_id/content hash are mandatory.

## 13. Scope

v0.3 must implement:

- export bundle metadata;
- manifest.json;
- manifest.csv;
- summary.json;
- contact sheets;
- stable IDs;
- review_patch.json import;
- AI suggestion layer;
- explicit accept/reject/clear actions.

Saved View export should reuse the same schema.

## 14. Acceptance

The feature passes when:

1. a real local dataset or View can be exported;
2. ChatGPT can refer to exact samples by stable ID;
3. a returned patch maps back to exact unchanged local samples;
4. renamed files remain resolvable;
5. changed/replaced files do not receive stale suggestions;
6. manual decisions are never silently overwritten;
7. bundle export itself does not mutate dataset state.
